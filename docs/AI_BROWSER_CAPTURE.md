# 学生网页摄像头接入与采样规范

修订日期：2026-11-13。

**产品方案：仅学生网页采集，AI 结果强制匿名，不保留公共摄像头入口。**
普通电脑的内置摄像头或 USB 摄像头即可作为输入；学生侧不安装 Python、
DeepFace、OpenCV、浏览器插件或本地采集程序。模型与依赖由管理员安装在独立 AI 服务主机上。

**实现状态要分清：** 当前版本已验证独立模型、服务认证、可靠匿名入库和原看板；
此前真实 USB 测试使用的是本机 Python 节点，**不是免安装浏览器采集**。
本文规定下一版网页采集的接入、授权、调度和验收要求；相关网页控件、采集会话 API、
多输入 AI 服务入口尚未交付，不能依据本文声称已能点击学生页面开始摄像头采集。

## 1. 为什么只保留学生网页采集

实验指导书 §3.1 要求 AI 服务独立部署，通过 REST 或消息提交结果；
§6 要求视频帧采样、至少五类映射、可配置频率/阈值、匿名化、重试和错误日志。
**没有要求公共摄像头、专用采集设备或固定的每节课采样次数。**

网页获取摄像头、服务器上的独立 Python 服务负责推理，仍符合上述分层要求。
原学生 MANUAL 反馈、课堂排课、教师查询、管理端看板与 CSV 保留，不新建第二套门户或数据库。

旧 USB/RTSP 节点不再作为正式用户操作路径；既有代码/测试只作为迁移过程的历史证据和回归工具。
替换完成前须明确显示过渡状态，不能将节点控制页换个名称就当成网页采集功能。

## 2. 谁采集、谁推理、结果保存什么

```text
学生电脑：原 Vue 学生课堂页面
  登录 → 选择已排课课堂 → 主动授权摄像头 → 本机预览 → 定时取单帧
                              │ 短期受限上传授权 / HTTPS
                              ▼
服务器：独立 Python AI 服务
  有界内存接收 → 人脸检测 → 单人检查 → 表情分类 → 置信度过滤
                              │ 独立服务凭证 / 原后端 API
                              ▼
原 FastAPI / 同一业务数据库
  课堂授权校验 → 事务 receipt / 幂等 → 匿名 EmojiRecord
                              ▼
原教师课堂 / 管理端看板 / 统计 / CSV
```

- 摄像头是学生当前电脑的摄像头，不是服务器上的摄像头。
- 学生登录用于排课授权、配额和防重复，不用于给表情记录填写姓名或学号。
- 所有 AI 业务记录 `user_id=None`；教师不能据表情结果界面查询学生的摄像头账号映射。
- 学生用户 `token` 只能申请/停止自己的采集会话，不能提交 AI 标签或置信度。
- 长期 AI 服务凭证只在服务器受限存储中存在，不进入浏览器、源码、URL 或页面持久化存储。
- 浏览器只拿到短期、单课堂/单采集会话、限定上传用途的授权。
- **网页路线需要上传采样帧供服务器推理。** “结果匿名、不保存原图”不等于“不传输原图”。
  原始帧只在浏览器和 AI 服务内存中短暂存在，不落业务库、临时文件、outbox、日志、trace 或录像。
- 只重试已生成的元数据事件；网络恢复后不补传课堂历史图片。

“结果匿名”不承诺整个鉴权系统完全不可关联；采集授权的临时控制信息必须有明确过期、
撤销和清理机制，与长期表情结果分开，不能把身份线索塞入 `device_source` 或 CSV。

## 3. 学生操作流程（目标交互，待实现）

入口沿用 `/student/classroom`，不新增独立设备配置页面：

1. 使用原学生账号登录，选择自己的已排课课堂。
2. 页面显示采集用途、匿名规则、课堂时间和本次采样间隔。
3. 点击「开启摄像头」，浏览器弹出权限提示；学生自己允许后才可获取画面。
4. 看到本机预览，点击「开始采集」。页面只保留状态、间隔、有效观测数与暂停/停止按钮。
5. 保持单人入镜。无人脸、多人或低分时显示原因，不产生强行映射的记录。
6. 点击「暂停」应停止采样并释放摄像头；「恢复」必须仍有有效课堂授权。
7. 点击「停止」、退出账号、切换账号/课堂、课堂结束或授权失效后释放全部摄像头 track，
   中止在途上传，并撤销采集会话。老师开启课堂不能代替学生同意摄像头权限。

拒绝摄像头权限、没有摄像头或不想参加自动采集时，原 MANUAL 反馈照常可用。
不要求学生整节课持续授权，也不以未采集作为缺勤或评分依据。

生产网页与帧上传入口使用 HTTPS；本机开发走 `localhost`。
局域网部署不能把另一台电脑的 `localhost` 当作服务器地址，
也不能为了获取摄像头而要求学生安装证书绕过工具或关闭浏览器安全限制。
浏览器/系统权限、兼容性和设备选择必须作为真实验收项，不仅依赖模拟视频输入。

## 4. 教师和管理员的操作边界

### 教师

在原课堂详情设置采样间隔、开启/暂停/结束本课堂自动采集，
查看匿名分布、有效观测数、无脸/多人/过滤/网络异常计数。
不选择学生摄像头索引，不分配每位学生的设备凭证，不查看原始视频。

常用页面只显示课堂状态与启停；模型版本、检测阈值和容量信息放在折叠的高级区，
避免每个页面重复展示整套设备管理表单。

### 管理员

负责一次性部署后端、Web、独立 AI 服务、模型准备、HTTPS入口和容量限制。
学生机器不安装模型；管理员使用的服务身份不是“每位学生一份永久设备 token”。

部署验收至少包括：

1. 后端健康检查、迁移和原 A/B/C 功能通过。
2. AI 服务模型校验及预热通过；缺模型不得 fallback 到假结果。
3. Web 入口和独立帧入口的 TLS、来源、短期授权验证通过。
4. request body/图片尺寸/格式/上传速率/并发限制在读取和推理前执行，
   网关、应用、错误日志均不保存请求图片或凭证。
5. 一台普通电脑实际授权摄像头，单帧 → 真模型 → 服务认证 API → 匿名记录 → 原看板通过。
6. 两个学生及多标签页隔离、停止释放、课堂结束与网络故障通过。
7. 测过对应班级规模后，才将采样配置投入课堂；不能把单人测试当成全班吞吐证明。

服务配置和凭证写入本地忽略目录或部署 secret store；正式文档、源代码和测试提交 Git，
权重、原图、运行配置和私人规划不提交。

## 5. 一节课采样多少次

实验没有固定次数。采用按时间调度，而不是“每节课必须凑够多少条记录”。
**建议的待验证默认间隔：10 秒；教师可选择 5、10、15、30 秒。**

从采集开始立即取样、课堂采用半开时间窗 `[start,end)` 时，连续采集的理论上限：

```text
单端采样次数 = ceil(采集持续秒数 / 采样间隔秒数)
平均请求速率 = 同时采集端数 / 采样间隔秒数
```

| 间隔 | 45 分钟 / 每端 | 90 分钟 / 每端 | 50 端平均输入 |
| --- | ---: | ---: | ---: |
| 5 秒 | 540 次 | 1080 次 | 10 帧/秒 |
| **10 秒** | **270 次** | **540 次** | **5 帧/秒** |
| 15 秒 | 180 次 | 360 次 | 约 3.33 帧/秒 |
| 30 秒 | 90 次 | 180 次 | 约 1.67 帧/秒 |

例如 50 端、45 分钟、10 秒间隔，理论最多 13500 次采样请求。
这些是时间预算，**不是已经实测的服务器吞吐、准确率或有效记录数**。
学生晚加入、暂停、掉线、页面后台、多人入镜、无脸或低置信度均会减少有效记录。

10 秒是兼顾趋势粒度与负载的工程起点，不是经课堂标注研究证明的最佳间隔。
2 秒留作短期模型/链路调试，不作为全班默认。正式班级应比较 5/10/15/30 秒下的
可见趋势、拒识率、排队与延迟，再决定配置；不能只依据单张图片的推理耗时估算容量。

### 调度规则

- 摄像头预览刷新率和 AI 采样率分开；预览连续并不意味着每帧上传或录像。
- 使用课堂时间槽以及分散的端点相位，避免全班同时开始导致同一秒集中上传。
- 每端最多一个在途请求；繁忙或错过时间槽直接跳过，不累计任务补发。
- 服务端限制同一采集端每时间槽最多一条有效观测；更换标签页/重启不能重置配额。
- 页面进入后台可暂停采样，恢复后从下一个时间槽继续，不补拍、不补传旧帧。
- 课堂结束、教师停止、学生停止或授权失效后不产生新观测；
  停止前已经授权生成的元数据仅按既有有界重试规则处理。

## 6. 如何避免重复

匿名模式不做人脸识别，也不保存身份 embedding。防重复分成三种不同问题：

| 问题 | 处理要求 |
| --- | --- |
| 同一学生多标签页/多设备启动 | 后端唯一活动采集会话；超时/撤销可释放，不只靠浏览器锁 |
| 重复点击、网络响应丢失、重传 | 稳定 frame/event UUID、服务端领取与事务 receipt；同事件只有一次业务效果 |
| 一个人被多台不同账号摄像头拍到 | 单人入镜规则减少风险；匿名且无身份识别时不能保证跨摄像头绝对去重 |

单人检查必须发生在“挑选通过表情阈值的观测”之前：
检测到两张脸即跳过整帧，不能因另一张脸太小或表情低分而把帧当成单人。
在检测范围内没有脸时也跳过，不能写成 `NEUTRAL`。
检测漏掉背景脸的可能性应在验收中记录，单人门不等于人员身份核验。

同一个人在不同时间槽产生不同观测，是时间序列采样，不是网络重复数据。
看板显示“AI 观测条数”，不能用其替代唯一学生人数。
多人之间的采样时长不同也会影响分布；没有身份归属的匿名结果不能假装做了逐学生等权统计。

## 7. 验收与故障清单

| 情况 | 期望结果 |
| --- | --- |
| 普通电脑内置/USB摄像头 | 网页授权、预览、真实单帧推理、匿名入库通过 |
| 权限拒绝 / 无摄像头 / 摄像头被占用 | 中文提示，不启动假采集；MANUAL可用 |
| 无人脸 | 无脸计数增加，AI记录不增加 |
| 多人入镜 | 多人计数增加，整帧不入库 |
| 低分 / unsupported emotion | 过滤计数增加，不强行改成五类之一 |
| 多标签页 / 重复请求 | 一个活动会话，同一事件只有一次记录 |
| 未排课 / 其他课堂 / 用户JWT写AI | 服务端拒绝，不以隐藏按钮代替权限验证 |
| 过期 / 撤销 / 课堂结束 / 登出 | 停止 track、上传和新入库 |
| 断网 / 服务繁忙 | 有界等待、丢弃错过帧，不缓存或补传原始图像 |
| 原看板 / 统计 / CSV / 学生历史 | 原契约保留，AI仍匿名，不混入学生个人历史 |

以上浏览器能力须在实际实现后逐项记录通过/未通过。
2026-11-13 的本机 USB 首测证据见 `AI_TEST_REPORT.md`；
它验证旧独立节点链路，不计为本规范的网页采集验收。
